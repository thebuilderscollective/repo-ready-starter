# Feature PRDs

A PRD (product requirements document) describes a particular feature or change.
The product brief describes the overall product. Keep one product.md and add
PRDs over time when work needs its own scope, decisions, and acceptance criteria.

| PRD | Status | Purpose |
| --- | --- | --- |
| [001-waitlist.md](001-waitlist.md) | Example / proposed | First interest-collection flow |
| [002-email-confirmation.md](002-email-confirmation.md) | Example / proposed | Follow-up feature after the waitlist works |

Useful statuses: proposed, building, shipped, superseded. Record an owner and
review date. Link related tasks, decisions, and evals instead of copying them.

For small changes, a task may be enough. When a feature ships, update product.md
and the affected docs; mark the PRD shipped. Supersede a substantially changed
plan with a link to the new one instead of maintaining competing current plans.
